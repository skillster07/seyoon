## 연출 콘셉트: "작은 빛 하나가 세상이 된다"
스토리보드의 고정 구도를 버리고, 내레이션 세 문장을 **한 번의 연속된 변화**로 보여 줍니다.

| 시간 | 내레이션 | 화면 | 구도 |
|---|---|---|---|
| 0–1.2s | — | 어둠, 별만 | 카메라가 가까이서 시작 |
| 1.2–2.4s | 한 아이가 태어납니다. | 화면 한가운데 **작은 빛 하나**가 두 번 박동(심장 박동 리듬), 가로 렌즈 줄기 | 정중앙, 대칭 |
| 2.4–4.0s | (호흡) | 빛이 부풀며 **원형 창이 빛에서 열림**. 후광이 번지고 링이 그려짐 | 정중앙 |
| 4.0–5.7s | 작은 시작이, 세상을 바꿉니다. | 창이 **오른쪽 1/3로 이동**, 창에서 빛 입자가 바깥으로 퍼짐, 왼쪽에 카피 등장 | 대칭에서 3분할로 |
| 0–5.6s | | 카메라 **풀백**(가까이 → 넓게) = 세상이 넓어짐 | |
| 5.6–12s | | 카메라 아주 느린 푸시인 | |
| 8.2–11.0s | 오늘의 작은 빛이, 우리의 내일을 밝힙니다. | 화면 아래 **빛의 길**이 왼쪽에서 오른쪽으로 그려지고, 길 위의 **작은 별 6개**가 차례로 켜짐 | |
| 11.0–12s | | 카피 퇴장, 빛의 길은 화면 밖 오른쪽으로 → SC02 | |

- **핵심 문장과의 연결:** "작은 빛 → 창(아이) → 퍼지는 빛(세상) → 빛의 길과 작은 별들(내일)". 수정 원고의 핵심 문장 "오늘의 작은 별들이 더 밝은 내일을 만듭니다"와 SC14 별 엔딩을 앞에서 미리 암시합니다.
- **PPT 느낌을 없애는 방법:** 구도가 한 번 크게 바뀌고(중앙 → 3분할), 카메라가 방향을 한 번 바꾸고(풀백 → 푸시인), 모든 등장이 앞 동작에서 이어집니다.

## 기술 변경
- **광원을 AE 기본 셰이프로 교체:** Saber를 쓰지 않습니다. 점광, 링, 궤도, 빛의 길을 셰이프 선과 채우기로 만들고, 가우시안 블러 복제본을 겹쳐 글로우를 냅니다. 파라미터를 추측할 필요가 없어서 결과를 예측할 수 있습니다.
- **HERO_RIG:** 창·후광·링·궤도·입자가 모두 하나의 널에 붙어 함께 움직입니다. 최종 위치는 CTRL `Hero X End`/`Hero Y End`로 정합니다.
- **얼굴 보호:** 창은 스텐실로 원 밖이 잘립니다. 궤도·후광·점광·플레어·빛의 길은 창 뒤 평면에 있어서 얼굴 앞으로 지나가지 않습니다. 창 앞에 있는 입자와 보케는 창 위에 구멍을 냅니다(v04.1).
- **타이포:** 56 / 90px, 자간 정착은 +14 → 0을 2.4초 동안. 왼쪽 단의 너비는 약 700px입니다. 링과의 간격은 상한 추정 124–129px입니다(아래 검증 참고). 150px 이상은 확인되지 않았습니다.
- **Glow:** 임계값 72%, 반경 70 한 단만. 광원 자체에 글로우가 있으므로 전체 블룸은 보조입니다(`Bloom %` 40).

## CTRL 슬라이더
- 타이밍: `Point Start` 1.2 / `Bloom Start` 2.4 / `Layout Start` 4.0 / `Text Start` 4.8 / `Path Start` 8.2. 가이드 녹음 후 이 다섯 개만 옮기면 됩니다.

## 검증 범위 (v04.1)
- **확인함:**
  - JSX 문법과 ES3 호환, 한글 코드값 저장(빌더 파일은 순수 ASCII).
  - AE 스크립팅 가이드에 있는 enum만 허용하는 모의 실행을 수동·자동화 두 모드 모두 끝까지 실행했습니다. 레이어 표현식 86개의 문법 오류는 0입니다.
  - `node src/test/geometry_check.cjs`: 빌더의 카메라·리그·타이밍 계산을 그대로 옮겨 1.9 / 3.2 / 4.9 / 6.8 / 9.4 / 11.2초를 검사했습니다. 원칙 ①② 실패 0, 경고 3.
- **경고(수정 안 함):** `ORBIT_B`의 왼쪽 아래 호가 "세상을 바꿉니다" 오른쪽 위 모서리에서 54–56px까지 옵니다(6.8/9.4/11.2초). 겹치지는 않지만 가깝습니다. 호는 회전하는 30% 트림이라 항상 그 자리에 있지는 않습니다. 렌더에서 붙어 보이면 빌더의 `ORBIT_SHIFT`를 90 → 130으로 올리거나 `ORBIT_B` 반지름을 R+230 → R+190으로 줄이십시오.
- **가정:** 얼굴은 창 반지름의 중앙 80% 안에 있다고 봤습니다(실제 촬영본 미확인). 글자 폭은 상한값입니다(한글 1.0em, 공백 0.33em, 라틴 대문자 0.72em). 블러 도달 거리는 블러 값과 같다고 근사했습니다.
- **확인 못 함:** 실제 AE 렌더의 밝기와 질감, 즉 원칙 ③ 전체입니다. 블러 글로우의 실제 강도, CC Star Burst 입자의 모양, `RUN_AUTO_SC01_v04.jsx`와 아래 명령의 실제 동작도 확인하지 못했습니다. 이 저장소 환경에는 After Effects가 없습니다.

## Mac 검수 루프 (이 환경에서 실행 검증 안 됨)
준비: AE 환경설정 > 스크립팅 및 표현식 > "스크립트가 파일을 쓰고 네트워크에 액세스하도록 허용". Output Module 템플릿 하나를 PNG Sequence로 만들어 `PNG_SEQ`로 저장합니다(편집 > 템플릿 > 출력 모듈).

```sh
D="/ABS/PATH/AHENG_SC01_AE_v04"          # BUILD_SC01_v04.jsx, RUN_AUTO_SC01_v04.jsx가 있는 폴더
AER="/Applications/Adobe After Effects 2026/aerender"
# 1) 빌드: 열린 프로젝트를 저장 없이 닫고 새로 만든 뒤 $D/AHENG_SC01_v04_EDITABLE.aep를 덮어씀
osascript -e "tell application \"Adobe After Effects 2026\" to DoScriptFile \"$D/RUN_AUTO_SC01_v04.jsx\""
cat "$D/BUILD_LOG_SC01_v04_latest.txt"
# 2) 검수 프레임(30fps): 1.9s=57  3.2s=96  4.9s=147  6.8s=204  9.4s=282  11.2s=336
mkdir -p "$D/review"
for f in 57 96 147 204 282 336; do
  "$AER" -project "$D/AHENG_SC01_v04_EDITABLE.aep" -comp "SC01_v04_MAIN" -s $f -e $f \
         -OMtemplate "PNG_SEQ" -output "$D/review/SC01_v04_[#####].png"
done
```
빛 조정 순서는 위 **룩 조정 순서**와 같습니다. 원칙 ③(얼굴이 가장 밝은 요소)은 실제 아기 촬영본을 `SRC_BABY_PLATE`에 넣은 뒤에만 판단할 수 있습니다. 회색 플레이스홀더로는 판단할 수 없습니다.
